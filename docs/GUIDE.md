## Что это и зачем

**Qwen Code** — бесплатный робот-программист, который живёт в терминале. Он умеет
читать твой код, править файлы, запускать команды, искать по проекту и объяснять,
что происходит. Аналог Claude Code, только с открытым исходным кодом.

Проблема в том, что «голый» Qwen Code почти бесполезен:

- **ему нужна модель.** Сам он ничего не соображает — он отправляет задачи большой
  нейросети. Бесплатную раздачу от Alibaba закрыли, и все старые инструкции
  перестали работать.
- **он пустой.** Ни команд, ни помощников, ни твоих правил проекта.
- **он не понимает настройки Claude Code.** Если ты пользовался платным Claude Code
  и накопил заготовки, просто скопировать их не выйдет.

**qwenkit закрывает все три задачи.** Это набор из восьми команд, которые
ставятся за пять минут и не требуют ничего, кроме Python.

Вот они целиком — этого достаточно, чтобы понять, нужен ли он тебе:

| Команда | Когда запускать | Что сделает |
| --- | --- | --- |
| `qwenkit doctor` | что-то не работает, не ставится или непонятно, чего не хватает | проверит Node.js, `qwen`, сеть, ключи и `settings.json` и скажет, что чинить |
| `qwenkit providers` | нужен бесплатный ключ | покажет провайдеров, лимиты и ссылки, где брать ключ |
| `qwenkit setup` | ключ уже есть | поставит Qwen Code и запишет `~/.qwen/settings.json` |
| `qwenkit probe` | после `setup` — или когда модель «вроде есть, но агент не работает» | живым запросом проверит, умеет ли модель вызывать инструменты |
| `qwenkit convert` | ты работал в Claude Code и хочешь перенести наработки | перенесёт `CLAUDE.md`, команды, помощников, MCP и настройки |
| `qwenkit pack` | хочется готовых `/команд` и помощников | поставит 8 команд и 6 субагентов |
| `qwenkit search` | нужны чужие наборы агентов | поищет их на GitHub |
| `qwenkit install` | набор уже найден | поставит его с конвертацией в формат Qwen Code |

Дальше идёт пошаговая настройка с нуля — можно просто повторять команды.

## Три минуты теории: как это устроено

```
┌─────────────────┐      запросы       ┌──────────────────┐
│  Qwen Code      │ ─────────────────► │  Модель (Qwen,   │
│  (робот в       │                    │  DeepSeek, GLM)  │
│   терминале)    │ ◄───────────────── │  у провайдера    │
└─────────────────┘      ответы        └──────────────────┘
         ▲
         │ читает настройки, команды и описания помощников
         │
┌────────┴────────┐
│  ~/.qwen/       │  ← вот это и настраивает qwenkit
│   settings.json │     (куда обращаться и какой ключ использовать)
│   commands/     │     (твои команды, например /review)
│   agents/       │     (помощники, например ревьюер)
│   QWEN.md       │     (правила, которые робот помнит всегда)
└─────────────────┘
```

Три вещи, которые стоит понять сразу:

**1. Робот и модель — разное.** Qwen Code установлен на твоём компьютере и
бесплатен навсегда. Модель живёт у провайдера и считается по запросам. Платишь
(или не платишь) ты только за модель.

**2. Запросы, а не токены.** Бесплатные тарифы считают именно запросы. Один твой
ход в диалоге — это не один запрос: робот может 10–20 раз сходить к модели, пока
читает файлы, думает и правит код. Поэтому «2000 запросов в день» на практике
означают примерно 100–200 осмысленных ходов. Для работы хватает.

**3. Настройки — это просто текстовые файлы.** Всё, что ставит qwenkit, лежит в
`~/.qwen/` (для всех проектов) или в `.qwen/` внутри проекта (только для него).
Можно открыть в блокноте и поправить руками. Никакой магии и никаких фоновых
процессов.

## Что понадобится

| Нужно | Зачем | Проверить |
| --- | --- | --- |
| **Python 3.9+** | на нём написан qwenkit | `python3 --version` |
| **Node.js 20+** | на нём написан сам Qwen Code | `node -v` |
| **pyyaml** | единственная библиотека qwenkit | ставится одной командой |
| **Бесплатный ключ API** | чтобы модель отвечала | получаем на шаге 1 |
| **Интернет** | для модели | — |

Node.js — единственное, что, возможно, придётся поставить. Скачай LTS-версию с
[nodejs.org](https://nodejs.org) и установи как обычную программу.

Если хочется вообще без интернета и без ключей — есть вариант с локальными
моделями, но он требует 16+ ГБ памяти. Об этом в разделе
[«Совсем без интернета»](#совсем-без-интернета-локальные-модели).

## Установка qwenkit

Скачай или склонируй проект и поставь зависимость:

```bash
git clone https://github.com/vovadruzhinin/qwenkit.git
cd qwenkit
pip install -r requirements.txt
```

Теперь qwenkit можно запускать так:

```bash
python3 qwenkit-cli doctor
```

Это работает везде, но длинно. Три способа сделать короче:

**Вариант 1 — установить как пакет** (появится команда `qwenkit`):

```bash
pip install .
qwenkit doctor
```

**Вариант 2 — симлинк** (Linux/macOS):

```bash
ln -s "$PWD/qwenkit-cli" ~/.local/bin/qwenkit
qwenkit doctor
```

**Вариант 3 — Windows.** В папке проекта есть `qwenkit.cmd`. Добавь эту папку в
`PATH` и пиши просто `qwenkit doctor`. Либо запускай через
`python qwenkit-cli doctor`.

Дальше в руководстве везде используется короткая форма `qwenkit`. Если ты
выбрал запуск через `python3 qwenkit-cli` — просто подставляй её вместо `qwenkit`.

## Шаг 1. Получаем бесплатный ключ

Рекомендую **ModelScope** — это платформа Alibaba, там лежат родные модели Qwen,
и там самая щедрая бесплатная квота: около **2000 запросов в день**, которые
сбрасываются каждые сутки.

1. Зайди на [modelscope.ai](https://modelscope.ai) и зарегистрируйся
   (можно через GitHub или Google — это быстрее всего).
2. Открой страницу токена: [modelscope.ai/my/myaccesstoken](https://modelscope.ai/my/myaccesstoken).
   Для китайской версии платформы это
   [modelscope.cn/my/myaccesstoken](https://modelscope.cn/my/myaccesstoken).
3. Скопируй токен. Он выглядит примерно как `ms-abc123...`.
4. Если страница просит привязать аккаунт Alibaba Cloud — привяжи, это бесплатно
   и нужно для доступа к API.

Теперь скажи ключ своему терминалу. **Это надо делать в каждом новом окне
терминала**, если не прописать ключ в профиль оболочки (как прописать — ниже).

Linux и macOS:

```bash
export MODELSCOPE_API_KEY='ms-твой-ключ'
```

Windows, PowerShell:

```powershell
$env:MODELSCOPE_API_KEY='ms-твой-ключ'
```

Windows, командная строка cmd:

```cmd
setx MODELSCOPE_API_KEY "ms-твой-ключ"
```

> После `setx` нужно **закрыть и открыть терминал заново** — иначе переменная
> не появится.

### Прописать ключ навсегда

Чтобы не вводить каждый раз:

**Linux/macOS** — добавь строку в `~/.bashrc` или `~/.zshrc`:

```bash
echo "export MODELSCOPE_API_KEY='ms-твой-ключ'" >> ~/.bashrc
source ~/.bashrc
```

**Windows (PowerShell)** — выполни один раз:

```powershell
[Environment]::SetEnvironmentVariable('MODELSCOPE_API_KEY','ms-твой-ключ','User')
```

> **Никогда не вставляй ключ в файлы проекта и не коммить его в git.** qwenkit
> специально сделан так, чтобы ключ жил в переменной окружения, а не в настройках.

## Шаг 2. Проверяем окружение

```bash
qwenkit doctor
```

Команда проходит четыре проверки и печатает понятный отчёт:

```
[1/4] Окружение
  ✓ ОС: Linux · Python 3.11.2
  ✓ Node.js v20.20.2 (нужен ≥20)
  ✓ npm найден
  ! Qwen Code не установлен
  → npm install -g @qwen-code/qwen-code@latest

[2/4] Доступность провайдеров
  ModelScope API-Inference (Alibaba)         доступен
  OpenRouter (:free модели)                  доступен
  Groq (free tier)                           жив (нужен ключ: HTTP 401)
  ...

[3/4] API-ключи в окружении
  ✓ MODELSCOPE_API_KEY = ms-abc…xyz  (ModelScope API-Inference)

[4/4] Конфигурация Qwen Code
  ! /home/user/.qwen/settings.json не существует
  → Запустите `qwenkit setup --provider modelscope`
```

Значки: `✓` — хорошо, `!` — внимание, `✗` — проблема. В конце всегда печатается
список «что делать дальше» именно для твоей ситуации.

**Про второй блок.** «жив (нужен ключ: HTTP 401)» — это **хорошо**. Значит,
сервер отвечает и просто ждёт ключ. Плохо — это «недоступен».

## Шаг 3. Подключаем модель

```bash
qwenkit setup --provider modelscope --install --refresh-models
```

Что делают флаги:

| Флаг | Зачем |
| --- | --- |
| `--provider modelscope` | какой провайдер подключаем |
| `--install` | заодно поставить сам Qwen Code через npm |
| `--refresh-models` | спросить у провайдера **актуальный** список моделей, а не брать встроенный |

Команда скачает Qwen Code (занимает около минуты) и создаст
`~/.qwen/settings.json`. Ключ при этом в файл **не записывается** — там только
ссылка на переменную окружения.

Полезные дополнения:

```bash
# посмотреть, какой JSON получится, ничего не записывая
qwenkit setup --provider modelscope --dry-run

# сразу указать основную и «быструю» модель
qwenkit setup --provider modelscope --model "Qwen/Qwen3.8-27B" \
              --fast-model "Qwen/Qwen3.5-27B"

# подключить несколько провайдеров сразу — потом переключаешься через /model
qwenkit setup --provider modelscope --provider openrouter
```

**Быстрая модель** (`--fast-model`) используется для мелких фоновых задач и для
части помощников. Она дешевле и быстрее, основная — умнее.

Если setup напишет, что ключ не найден, — вернись к шагу 1 и убедись, что
`export` выполнен **в этом же окне терминала**.

## Шаг 4. Проверяем, что модель подходит

Это самый важный шаг, который все пропускают.

```bash
qwenkit probe --provider modelscope
```

Команда шлёт каждой модели настоящий запрос **с объявленным инструментом** и
смотрит, попыталась ли модель этот инструмент вызвать. Выглядит так:

```
ModelScope API-Inference (Alibaba)
  OK  Qwen/Qwen3.8-27B                tools ✓ 1.83s  142 ток
  OK  Qwen/Qwen3.5-397B-A17B          tools ✓ 3.11s  138 ток
  ERR Qwen/Qwen3.5-27B                HTTP 429: rate limit exceeded

Итог
  Годятся для Qwen Code (есть tool-calling):
    · modelscope:Qwen/Qwen3.8-27B  (1.83s)
    · modelscope:Qwen/Qwen3.5-397B-A17B  (3.11s)

  Рекомендация: qwenkit setup --provider modelscope --model Qwen/Qwen3.8-27B
```

**Почему это важно.** Qwen Code — агент: он не просто болтает, а вызывает
инструменты (прочитать файл, запустить команду, найти по тексту). Если модель не
поддерживает tool-calling, робот **не сможет сделать ничего**, даже если обычный
чат с ней работает нормально. Ошибка при этом будет невнятной, и можно потратить
вечер на поиски причины.

Возможные результаты:

| Что написано | Что это значит |
| --- | --- |
| `tools ✓` | модель подходит, можно работать |
| `tools ✗` | модель отвечает, но инструменты не вызывает — **для агента не годится** |
| `HTTP 401` | неверный или отсутствующий ключ |
| `HTTP 429` | кончилась дневная квота, попробуй завтра или другую модель |
| `ERR ... Timeout` | сеть или провайдер не отвечают |

В конце `probe` печатает готовую команду `setup` с лучшей моделью — можно просто
скопировать и выполнить.

## Шаг 5. Ставим команды и помощников

```bash
qwenkit pack --list        # сначала посмотреть, что там
qwenkit pack               # поставить
```

Установятся **8 команд** и **6 помощников** в `~/.qwen/` — они будут доступны во
всех твоих проектах.

### Команды

Набираешь `/` внутри Qwen Code и выбираешь:

| Команда | Что делает |
| --- | --- |
| `/git:commit` | смотрит на изменения и пишет сообщение коммита по стандарту Conventional Commits. Сам коммит **не делает** |
| `/review` | код-ревью: ищет баги, проблемы безопасности, гонки. Выдаёт вердикт и список замечаний по серьёзности |
| `/tests` | пишет тесты под тот фреймворк, который уже есть в проекте, и сразу их запускает |
| `/explain` | объясняет код: зачем он → как работает → карта сущностей → подводные камни |
| `/refactor` | упрощает код **без изменения поведения**, мелкими шагами с проверкой тестов |
| `/security` | аудит безопасности: секреты в коде, инъекции, утечки данных, уязвимые зависимости |
| `/doc` | точечно обновляет документацию под текущий код, находит расхождения |
| `/fix-ci` | разбирает падение сборки: ищет первопричину, а не симптом |

У команд есть аргументы. Например:

```
/review src/auth.py
/explain функция process_payment в billing.py
/tests модуль парсинга CSV
```

### Помощники (субагенты)

Это отдельные роботы со своей специализацией, своим контекстом и **ограниченным
набором инструментов**. Qwen Code обычно вызывает их сам, по описанию задачи.
Можно и явно: «запусти агента reviewer на этом диффе».

| Помощник | Специализация | Что умеет |
| --- | --- | --- |
| `reviewer` | код-ревью | **только читает** — физически не может ничего испортить |
| `tester` | тесты | читает, пишет, запускает |
| `researcher` | разведка кода | ищет и читает, работает на быстрой модели — дёшево |
| `documenter` | документация | читает и пишет текст |
| `refactorer` | рефакторинг | читает, пишет, запускает тесты |
| `python-expert` | сложные задачи на Python | всё перечисленное плюс интернет |

Зачем это нужно: основной робот не тащит в контекст десятки прочитанных файлов —
он спрашивает помощника, а тот возвращает только готовый вывод. Контекст
экономится, ответы становятся точнее.

### Куда ставить

```bash
qwenkit pack                        # в ~/.qwen — видно во всех проектах
qwenkit pack --target project       # в ./.qwen — только в этом проекте
qwenkit pack --only agents          # только помощников
qwenkit pack --overwrite            # заменить существующие (старые → .bak)
```

Проектные команды имеют приоритет над глобальными, поэтому для конкретного
репозитория можно сделать свои версии — и закоммитить их, чтобы команда
пользовалась тем же набором.

## Шаг 6. Работаем

```bash
cd твой-проект
qwen
```

Откроется диалог. Пиши по-русски обычными словами: «разберись, почему падает
тест авторизации», «добавь кэширование в этот метод», «объясни, что делает этот
модуль».

Первое, что стоит сделать в новом проекте:

```
/init
```

Робот прочитает кодовую базу и создаст `QWEN.md` — файл с правилами проекта:
команды сборки и тестов, принятые соглашения, архитектурные решения. Этот файл
загружается в начале каждого диалога, поэтому правила не приходится повторять.

Полезные команды внутри Qwen Code:

| Команда | Что делает |
| --- | --- |
| `/model` | сменить модель (все подключённые одним списком) |
| `/agents manage` | список и настройка помощников |
| `/mcp` | управление MCP-серверами |
| `/memory` | посмотреть, что робот помнит |
| `/init` | создать `QWEN.md` по кодовой базе |
| `/diff` | посмотреть, что изменено |
| `/help` | справка |

Три режима ввода:

- обычный текст — задача роботу;
- `/` — команды;
- `!` в начале строки — shell-команда напрямую;
- `@` — подставить файл в сообщение (`@src/main.py объясни это`).

## Перенос проекта с Claude Code

Если ты пользовался Claude Code, у тебя в проекте есть папка `.claude/` и,
возможно, файл `CLAUDE.md`. Напрямую Qwen Code их не понимает: другие имена
файлов, другой синтаксис подстановок, другие названия инструментов.

### Сначала смотрим, что будет

```bash
cd твой-проект
qwenkit convert --dry-run .
```

Ничего не изменится — команда только покажет план: какие файлы создаст, где
возникнут предупреждения и что придётся доделать руками. **Обязательно посмотри
этот вывод перед настоящей конвертацией.**

### Потом конвертируем

```bash
qwenkit convert .
```

Что произойдёт:

| Было | Станет |
| --- | --- |
| `CLAUDE.md` | `QWEN.md` |
| `CLAUDE.local.md` | `.qwen/QWEN.local.md` + правило в `.gitignore` |
| `.claude/commands/review.md` | `.qwen/commands/review.md` |
| `.claude/agents/tester.md` | `.qwen/agents/tester.md` |
| `.mcp.json` | `.qwen/.mcp.json` |
| `.claude/settings.json` | `.qwen/settings.json` (частично) |

Оригиналы **не удаляются** — `.claude/` остаётся на месте, Claude Code продолжит
работать как раньше. Если в `.qwen/` уже что-то лежало, старое уедет в
`.qwen-backup-<дата-время>/`.

### Что читать после конвертации

Открой созданный **`MIGRATION_TODO.md`**. Там два списка:

- **что сделать руками** — то, что автоматически перенести нельзя: правила
  разрешений (`permissions`), способ получения ключа (`apiKeyHelper`), статусная
  строка, папка со скриптами хуков;
- **предупреждения** — каждое с объяснением, что именно изменено и почему.

Предупреждения стоит прочитать, а не пролистать. Особенно такие:

> инструмент `KillShell` отброшен: в Qwen Code остановкой процесса управляет
> `run_shell_command`, отдельного инструмента нет. **ВАЖНО:** если он был в
> `disallowedTools`, ограничение снято — перепроверьте список вручную

Это значит, что запрет из Claude Code не перенёсся, и помощник теперь может
больше, чем ты планировал.

### Личные команды и помощники

Если ты держал команды не в проекте, а «для себя» — в `~/.claude/`, — их
переносит отдельная команда:

```bash
qwenkit convert --global
```

### Что конвертер делает с текстом команд

| В Claude Code | В Qwen Code | Смысл |
| --- | --- | --- |
| `$ARGUMENTS` | `{{args}}` | сюда подставят то, что ты написал после команды |
| `` !`git diff` `` | `!{git diff}` | выполнить команду и вставить вывод |
| `@docs/rules.md` | `@{docs/rules.md}` | вставить содержимое файла |

Всё это конвертируется автоматически, включая случаи внутри вложенных блоков.

## Чужие наборы агентов с GitHub

В интернете лежат сотни готовых наборов под Claude Code — это просто папки с
`.md`-файлами. qwenkit ставит их одной командой, сразу конвертируя.

### Найти

```bash
qwenkit search
qwenkit search "python agents"
```

Вывод — таблица репозиториев со звёздами, датой обновления и описанием:

```
  РЕПОЗИТОРИЙ                                    ЗВЁЗД  ОБНОВЛЁН    ОПИСАНИЕ
  wshobson/agents                                41627  2026-10-24  Multi-harness agentic plugin…
  VoltAgent/awesome-claude-code-subagents        25990  2026-10-11  A collection of 100+ speciali…
```

### Посмотреть, не устанавливая

```bash
qwenkit install owner/repo --dry-run
```

Покажет, сколько агентов и команд нашлось и как они будут называться. Файлы при
этом не скачиваются в проект и ничего не меняется.

### Установить

```bash
qwenkit install owner/repo                          # всё
qwenkit install owner/repo/agents                   # только подкаталог
qwenkit install owner/repo --only commands          # только команды
qwenkit install owner/repo --target-dir project     # в этот проект, а не глобально
qwenkit install owner/repo --prefix mypack-         # префикс имён, чтобы не пересеклось с твоим
```

Принимаются разные формы адреса:

```bash
qwenkit install wshobson/agents
qwenkit install https://github.com/wshobson/agents
qwenkit install https://github.com/wshobson/agents/tree/main/plugins/backend-development/agents
qwenkit install https://github.com/wshobson/agents/blob/main/agents/reviewer.md
```

### Что установлено и как удалить

```bash
qwenkit install --list                             # список
qwenkit install x --uninstall owner/repo           # удалить конкретный набор
qwenkit install x --uninstall --all                # удалить всё, что ставил qwenkit
```

Удаление точное: каждая установка пишется в манифест
`.qwen/.qwenkit-installed.json`, поэтому твои собственные файлы не пострадают.

### Как это находит агентов

Не все наборы хранят агентов в папке `agents/`. Крупнейшие лежат так:

```
categories/01-core-development/api-designer.md
categories/03-infrastructure/backend-developer.md
```

По пути их не отличить от документации. Поэтому qwenkit сначала смотрит на
пути, и если зацепок мало — скачивает `.md`-файлы и заглядывает внутрь: там, где
есть `name`, `description` и поля агента (`tools`, `model`, `color`), — это агент.
На репозитории из 198 файлов такой досмотр занимает около 10 секунд и находит
157 агентов.

Сами файлы качаются с хоста, который **не тратит** часовой лимит GitHub, поэтому
установка большого набора расходует буквально один запрос к API.

### ⚠️ Безопасность: прочитай перед установкой

Агенты и команды — это **инструкции, которые будет выполнять робот с доступом к
твоим файлам и терминалу**. Ставить чужой набор = пускать чужие инструкции в свой
проект.

Что qwenkit делает, чтобы снизить риск:

- чужие `.claude/settings.json` **не устанавливаются вообще** — именно там
  живут хуки, запускающие произвольные команды. Вместо этого печатается ссылка,
  чтобы ты посмотрел файл глазами;
- чужой `CLAUDE.md` **не подмешивается** в твой `QWEN.md` — он сохраняется в
  `.qwen/imported-notes/` для ознакомления;
- на каждую shell-вставку `!{...}` внутри команды выдаётся предупреждение;
- установка обратима: `--uninstall` убирает всё поставленное.

Чего qwenkit сделать не может — это прочитать набор за тебя. **Перед первым
запуском открой установленные файлы и пробегись глазами.** Особенно ищи:

- `!{...}` в командах — это выполняемые shell-команды;
- в тексте агентов просьбы «отправить», «загрузить», «выполнить curl»,
  «прочитать ~/.ssh» и подобное.

## Совсем без интернета: локальные модели

Если не хочется нигде регистрироваться и не хочется отправлять свой код на чужие серверы — есть
вариант с **Ollama**: модель работает прямо на твоём компьютере.

Плюсы: полностью бесплатно, без дневных лимитов, код никуда не уходит.
Минусы: нужна память, и качество ниже, чем у больших облачных моделей.

```bash
# 1. поставить Ollama
#    https://ollama.com/download

# 2. скачать модель (выбери одну)
ollama pull qwen3-coder:30b       # 24+ ГБ памяти — лучший вариант для агента
ollama pull qwen3:14b             # ~16 ГБ — разумный минимум
ollama pull qwen2.5-coder:7b      # ~8 ГБ — слабый, но запустится почти везде

# 3. подключить
qwenkit setup --provider ollama --install
qwenkit probe --provider ollama   # обязательно проверить tool-calling
```

Ключ для Ollama не нужен — qwenkit подставит заглушку сам.

**Практический совет.** Локальная модель на 7B часто не тянет агентную работу:
она путается в инструментах и зацикливается. Если выбираешь локальный путь, бери
14B и выше.

Можно подключить Ollama **вместе** с облачным провайдером и переключаться через
`/model`:

```bash
qwenkit setup --provider modelscope --provider ollama --install
```

## Когда что-то идёт не так

### `command not found: qwen` / «qwen не является внутренней командой»

Qwen Code не установлен или не попал в PATH.

```bash
npm install -g @qwen-code/qwen-code@latest
```

Если npm ругается на права (`EACCES`, `permission denied`) — **не используй
sudo**. Настрой npm в домашний каталог:

```bash
npm config set prefix ~/.npm-global
echo 'export PATH=~/.npm-global/bin:$PATH' >> ~/.bashrc
source ~/.bashrc
npm install -g @qwen-code/qwen-code@latest
```

Либо запускай без установки: `npx @qwen-code/qwen-code`.

### `API Error: 401 Authentication failed`

Ключ не дошёл до робота. Проверь по порядку:

```bash
echo $MODELSCOPE_API_KEY          # Linux/macOS — должно напечатать ключ
echo $env:MODELSCOPE_API_KEY      # Windows PowerShell
qwenkit doctor                    # блок [3/4] покажет, видит ли ключ qwenkit
```

Частые причины: `export` выполнен в другом окне терминала; ключ скопирован с
лишними пробелами или кавычками внутри; после `setx` терминал не перезапущен.

### `API Error: 429` или «rate limit»

Кончилась дневная квота. Варианты:

- подождать до следующего дня (квота сбрасывается каждые сутки);
- переключиться на другую модель того же провайдера — иногда лимиты считаются
  по моделям: внутри Qwen Code набери `/model`;
- подключить второго провайдера: `qwenkit setup --provider openrouter`;
- проверить фактические лимиты: `qwenkit providers` печатает ссылки на страницы
  условий.

### Робот отвечает, но ничего не делает

Почти всегда это **отсутствие tool-calling** у модели. Проверь:

```bash
qwenkit probe --provider modelscope
```

Если у текущей модели `tools ✗` — выбери из списка ту, у которой `tools ✓`, и
переподключи:

```bash
qwenkit setup --provider modelscope --model "Модель/С-tools-✓"
```

### После `convert` команды не появляются

- Перезапусти Qwen Code — он читает `.qwen/commands/` при старте.
- Проверь, что ты в том же каталоге, где лежит `.qwen/`: команды из
  `.qwen/commands/git/commit.md` вызываются как `/git:commit`, а не `/commit`.
- Запусти `qwenkit doctor` — блок [4/4] показывает, видит ли он файлы.

### `convert` напечатал «нечего конвертировать»

В текущем каталоге нет ничего от Claude Code. Ожидаются `CLAUDE.md`, папка
`.claude/` или `.mcp.json`. Проверь, что ты в корне проекта, и посмотри скрытые
папки: `ls -a`.

Для личных (не проектных) настроек используется `qwenkit convert --global`.

### `install` сообщает про лимит GitHub

Без токена GitHub даёт 60 запросов к API в час. qwenkit тратит на установку
набора **один** запрос, но если ты ставишь много наборов подряд, лимит может
кончиться. Решение — бесплатный токен:

```bash
export GITHUB_TOKEN=ghp_...       # Linux/macOS
$env:GITHUB_TOKEN='ghp_...'       # Windows PowerShell
```

Токен создаётся на [github.com/settings/tokens](https://github.com/settings/tokens);
для публичных репозиториев достаточно токена вообще без разрешений.

### `install` не нашёл агентов в репозитории

Значит, в репозитории действительно нет файлов, похожих на агентов, либо они
лежат в неожиданном месте. Посмотри структуру глазами и укажи подкаталог:

```bash
qwenkit install owner/repo/путь/к/папке
```

### Всё сломалось, хочу начать с нуля

```bash
qwenkit install x --uninstall --all     # убрать чужие наборы
rm -rf ~/.qwen                          # снести все настройки Qwen Code
qwenkit setup --provider modelscope     # настроить заново
qwenkit pack                            # поставить набор
```

Проекты при этом не трогаются — удаляется только конфигурация робота.

## Шпаргалка по командам

### `qwenkit doctor`

| Флаг | Действие |
| --- | --- |
| `--offline` | не обращаться к сети, проверить только локальное окружение |

### `qwenkit setup`

| Флаг | Действие |
| --- | --- |
| `--provider X` | провайдер; можно повторить несколько раз |
| `--install` | поставить Qwen Code через npm, если его нет |
| `--refresh-models` | запросить актуальный список моделей у провайдера |
| `--model X` | основная модель |
| `--fast-model X` | быстрая модель для помощников |
| `--max-models N` | сколько моделей добавить (по умолчанию 10) |
| `--dry-run` | показать JSON, ничего не записывая |
| `--force` | перезаписать `settings.json` вместо объединения |
| `--store-key` | сохранить ключ прямо в `settings.json` (менее безопасно) |
| `--settings ПУТЬ` | свой путь к `settings.json` |

### `qwenkit probe`

| Флаг | Действие |
| --- | --- |
| `--provider X` | кого проверять (можно несколько раз) |
| `--model X` | какую модель проверять (можно несколько раз) |
| `--all-models` | проверить весь каталог провайдера |
| `--limit N` | сколько моделей проверить (по умолчанию 3) |
| `--include-paid` | проверять и платных провайдеров |
| `--api-key X` | ключ явно, вместо переменной окружения |

### `qwenkit convert`

| Флаг | Действие |
| --- | --- |
| `ПУТЬ` | корень проекта (по умолчанию текущий каталог) |
| `--global` | конвертировать `~/.claude` в `~/.qwen` |
| `--dry-run` | только показать план |
| `--no-report` | не создавать `MIGRATION_TODO.md` |

### `qwenkit pack`

| Флаг | Действие |
| --- | --- |
| `--list` | показать состав набора |
| `--target user\|project` | в `~/.qwen` или в `./.qwen` |
| `--only commands\|agents` | только часть набора |
| `--overwrite` | заменять существующие (старые → `.bak`) |
| `--dry-run` | показать, что будет создано |

### `qwenkit install`

| Флаг | Действие |
| --- | --- |
| `ЦЕЛЬ` | `owner/repo` или ссылка на GitHub |
| `--list` | показать, что установлено через qwenkit |
| `--uninstall OWNER/REPO` | удалить набор (или `--all`) |
| `--dry-run` | показать план |
| `--only X` | `agents`, `commands`, `mcp`, `memory` (можно повторить) |
| `--target-dir user\|project` | куда ставить |
| `--prefix X` | префикс имён файлов |
| `--ref X` | ветка, тег или коммит |
| `--overwrite` | заменять существующие |

### `qwenkit search`

| Флаг | Действие |
| --- | --- |
| `ЗАПРОС` | своя строка поиска (иначе — подобранные запросы) |
| `--limit N` | сколько репозиториев на запрос |
| `--min-stars N` | порог звёзд (по умолчанию 20) |

### `qwenkit providers`

Без флагов. Печатает справочник: base_url, имя переменной окружения, где взять
ключ, что именно бесплатно, список моделей — и живой каталог бесплатных моделей
OpenRouter с поддержкой tool-calling.

## Вопросы и ответы

**Это легально? Меня не забанят?**

Да, легально. qwenkit не взламывает ничего и не обходит оплату. ModelScope,
OpenRouter, Groq и Cloudflare — это официальные бесплатные тарифы: ты
регистрируешься, получаешь ключ и пользуешься в пределах заявленных лимитов.
Qwen Code сам по себе — программа с открытым исходным кодом, её установка
бесплатна всегда.

**Сколько это реально стоит?**

Нисколько, если оставаться в пределах бесплатных квот. ModelScope даёт около
2000 запросов в день — для обычной работы над одним-двумя проектами хватает.
Деньги понадобятся, только если захочешь самые сильные модели без ограничений.

**Мой код куда-то отправляется?**

Да — если используешь облачного провайдера. Модель не может прочитать твой код
иначе: qwenkit отправляет ему те файлы и команды, которые робот просит в рамках
задачи. Условия обработки смотри у провайдера.

Если это неприемлемо — используй Ollama: код остаётся на твоём компьютере.

**qwenkit собирает телеметрию?**

Нет. Он вообще никуда не подключается, кроме двух случаев: когда ты сам
запускаешь `doctor`, `probe`, `providers`, `search` или `install`. Фоновых
процессов нет, ничего не устанавливается в систему помимо того, что ты попросил.

**Чем это отличается от Claude Code?**

Claude Code — платный и использует модели Anthropic. Qwen Code — бесплатный, с
открытым кодом, и может работать на разных моделях, включая локальные. По
возможностям они близки: оба читают код, правят файлы, запускают команды и
поддерживают помощников и MCP-серверы. На сложных задачах платные модели пока
заметно сильнее, на рутине разница невелика.

**Можно пользоваться и тем, и другим одновременно?**

Да. `qwenkit convert` не удаляет `.claude/` — он создаёт рядом `.qwen/`. Оба
робота будут работать в одном проекте, каждый со своими настройками.

**Что такое MCP-серверы и зачем они?**

Это способ подключить к роботу внешние инструменты: доступ к GitHub, базе
данных, браузеру, Figma. MCP — общий стандарт, поэтому серверы, написанные для
Claude Code, работают и в Qwen Code **без переделки**. qwenkit просто копирует
их в конфиг.

**У меня Windows. Всё работает?**

Да. Все команды кроссплатформенные; в CI они прогоняются на Windows, macOS и
Linux. Нюансы два: для запуска `qwenkit` используй `python qwenkit-cli` или
обёртку `qwenkit.cmd`, а ключ задавай через `$env:ИМЯ='значение'` в PowerShell.

**Зачем нужны `--dry-run`?**

Посмотреть, что произойдёт, ничего не меняя. Особенно полезно перед `convert`
(чтобы увидеть предупреждения) и перед `install` чужого набора (чтобы понять,
сколько файлов приедет и как они назовутся).

**Я поставил чужой набор, и стало хуже. Как откатить?**

```bash
qwenkit install x --uninstall owner/repo
```

Удалятся ровно те файлы, которые поставил qwenkit. Твои собственные команды и
помощники останутся нетронутыми.

**Куда девать идеи и баги?**

В [issues репозитория](https://github.com/vovadruzhinin/qwenkit/issues). Если
речь о конвертере — приложи исходный файл из `.claude/` и результат из `.qwen/`,
этого достаточно для воспроизведения. Порядок работы описан в
[CONTRIBUTING.md](../CONTRIBUTING.md).
